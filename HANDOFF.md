# WidgetLab — редакторы скинов виджетов. Инструкция для разработчика

Живой сайт: **https://weeusle.github.io/wlab/** — стартовая страница с карточками. Каждая
карточка ведёт в отдельный редактор скина: слева превью виджета, справа панель настроек.

## 1. Как всё устроено

Есть **два места**:

| Что | Путь | Назначение |
|-----|------|-----------|
| Исходники редакторов | `/home/am/wlab/new widgets/` | Здесь ведётся разработка. Один скин = один Vite+Lit проект |
| Копия для публикации | `/home/am/wlab-pages/` | Git-репозиторий (ветка `gh-pages` репо `weeusle/wlab`). Сюда кладутся **собранные** бандлы. Вручную ничего не правим |

Структура одного скина, например `new widgets/Video/skin1/`:

- **`index.html`** — сам редактор (превью слева + панель настроек справа).
- **`src/`** — код виджета и логики превью (Lit-компоненты).
- **`formSettings.json`** — **описание правой панели**: какие поля, группы, типы, лейблы.
  Хочешь добавить/убрать/переименовать поле в панели — правь этот файл.
- **`defaultSettings.json`** — стартовые значения настроек (с чем открывается редактор).
- `vite.config.ts` — сборка. Важно: `base: './'` (Pages в подпапке) и `publicDir: false`.

## 2. Локальная разработка

```bash
cd "/home/am/wlab/new widgets/Video/skin1"   # нужный скин
npm install          # один раз
npm run dev          # локальный dev-сервер Vite, открыть в браузере
```

Правишь `index.html` / `src/` / `formSettings.json` → изменения видны сразу.

> ⚠️ Dev-сервер годится **только для локальной работы**. По внешнему IP он отдаёт сотни
> ES-модулей отдельными запросами и превью не инициализируется. На живой сайт публикуется
> **только собранный бандл** (см. ниже).

## 3. Публикация на живой сайт

Одна команда пересобирает **все** редакторы в бандлы и пушит на GitHub Pages:

```bash
bash /home/am/wlab-pages/redeploy.sh
```

Через ~1–2 минуты изменения на https://weeusle.github.io/wlab/

Для публикации нужен доступ на запись в репо `weeusle/wlab` (ветка `gh-pages`). Настроен
через SSH deploy-ключ `~/.ssh/wlab_deploy` и хост-алиас `github.com-wlab` в `~/.ssh/config`.
Если публикуешь со своей машины — заведи свой ключ/доступ к репозиторию.

## 4. Как добавить НОВЫЙ скин в редактор

1. Создай проект скина в `/home/am/wlab/new widgets/<Виджет>/<skinN>/` (проще всего —
   скопировать существующий скин как шаблон и переделать).
2. В `redeploy.sh` добавь строку сборки:
   ```bash
   build_one "/home/am/wlab/new widgets/<Виджет>/<skinN>" "<имя-на-сайте>"
   ```
   `<имя-на-сайте>` — это подпапка на сайте, напр. `video-skin2`.
3. В `/home/am/wlab-pages/index.html` добавь карточку на стартовую страницу:
   ```html
   <a class="card" href="./<имя-на-сайте>/"><b>Название</b><span>widget · skinN</span><div class="tag">Категория</div></a>
   ```
4. Запусти `bash /home/am/wlab-pages/redeploy.sh`.

## 5. Известные грабли

- **`Cannot find module @rollup/rollup-linux-x64-gnu`** при сборке (баг optional-deps npm).
  Лечится в папке скина:
  ```bash
  rm -rf node_modules package-lock.json && npm install
  ```
- Если превью на сайте пустое/«не отвечает» — почти всегда забыли собрать бандл
  (`redeploy.sh`) или в vite.config сбит `base: './'`.
- `defaultSettings.json` и `formSettings.json` не попадают в `dist` автоматически
  (`publicDir: false`) — `redeploy.sh` копирует их в бандл сам. При ручной сборке не забудь.
